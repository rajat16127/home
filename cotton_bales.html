1. Executive Summary & Architecture

In industrial cotton ginning and processing facilities, automated tracking of packaged cotton bales is critical for throughput monitoring, inventory verification, and operational transparency. Manual logging is labor-intensive and error-prone.

This project delivered an edge-ready computer vision solution that inspects factory camera feeds, continuously identifies large dense cotton bales emerging from industrial hydraulic presses, tracks them across a conveyor section, triggers an increment on a virtual crossing boundary, and generates real-time telemetry alongside audit snapshots for local and upstream ingestion.

Pipeline Execution Flow

Step 1: Frame Acquisition & Dynamic Sourcing Frames are streamed from factory RTSP endpoints or test video sources at runtime via an isolated configuration map.
Step 2: Object Detection & Persistent Multi-Object Tracking YOLO11n extracts class bounding boxes (cotton-bale) with confidence and IoU threshold filtering. Frame-to-frame identity persistence is maintained using multi-object tracking (model.track(persist=True)).
Step 3: Signed 2D Vector Boundary Trajectory Calculation Centroid coordinates $(x_c, y_c)$ of each tracked bale ID are evaluated against a parameterized 2-point directional boundary line. Crossing is recognized through polarity change of the vector cross-product.
Step 4: Atomic Logging & Audit Artifact Generation Upon valid transition, the counter increments. Simultaneously, an annotated frame snapshot with bounding coordinates and an accompanying ISO timestamped JSON payload are flushed to the mapped host filesystem.

2. Data Engineering & Selective Curation

Training data was curated from raw industrial factory footage provided by the operational team:

  • Static Warehouse Feed (2 minutes): Showed stationary cotton bales stacked in a storage facility with ambient industrial dust and variable lighting. Because immediate consecutive frames were redundant, frames were sparsely sampled, and deliberate spatial augmentation (selective cropping, zooming, aspect ratio adjustments) was applied to teach the model invariance to bale texture, stacking edges, and distance.
  • Active Press & Conveyor Feed (>30 minutes): Captured workers operating a large hydraulic press producing cuboid cotton bales every few minutes, which were moved onto short conveyor paths and transported on trolleys. A key challenge was the sparsity of bale appearances. Redundant idle machine frames and near-duplicate successive frames were discarded via selective sampling, preserving only informative frames containing emergence, translation, and human-object interactions.
  • Annotation: Filtered datasets were imported into Roboflow for bounding-box annotation under a single target class (cotton-bale), followed by augmentation pipelines (geometric shifts, brightness perturbations) prior to model training.

Vector Line Side Verification

To support tilted conveyor angles and diverse camera perspectives across facilities, the counting boundary is defined in annotation.cfg using normalized coordinates LINE_P1 and LINE_P2. Rather than using standard horizontal or vertical axis thresholds, the crossing logic calculates the signed determinant (2D cross product) of the vector from line point $P_1$ to bale centroid $P$ relative to the directional vector $P_1 \to P_2$: 

side = (point.x - p1.x) * (p2.y - p1.y) - (point.y - p1.y) * (p2.x - p1.x)

When an actively tracked object transitions from a negative sign to a non-negative sign (prev_side < 0 and current_side >= 0), a forward crossing is detected. A unique tracking ID set (tracked_ids) prevents duplicate triggers if a bale pauses or decelerates on the boundary.

6. Containerization & Decoupled Configuration

To facilitate zero-configuration deployment across factory facilities without requiring local CUDA or Python dependency management, the application was packaged into a lightweight Docker image.

The architecture explicitly separates application logic from deployment variables via Docker volume mounting. Camera RTSP URLs, counting line coordinates, and threshold values can be reconfigured in annotation.cfg on the host machine without rebuilding the container image. 

# Pull production container image from Docker Hub
docker pull rajat16127/bale_counter:v2.0

# Execute inference on edge CPU with dynamic host mounts
sudo docker run --rm \
  -v /path/to/host/folder:/data \
  -v /path/to/host/folder/annotation.cfg:/app/annotation.cfg \
  rajat16127/bale_counter:v2.0
